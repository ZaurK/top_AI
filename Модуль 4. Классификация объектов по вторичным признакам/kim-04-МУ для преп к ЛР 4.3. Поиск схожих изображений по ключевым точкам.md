# МЕТОДИЧЕСКИЕ УКАЗАНИЯ ДЛЯ ПРЕПОДАВАТЕЛЯ

к лабораторной работе «Поиск схожих изображений по ключевым точкам»

по дисциплине «Компьютерное зрение»

---

## 1. ЦЕЛИ И ЗАДАЧИ ЛАБОРАТОРНОЙ РАБОТЫ

### 1.1. Образовательные цели
- Закрепить теоретические знания о детекторах ключевых точек и дескрипторах.
- Сформировать практические навыки реализации полного пайплайна поиска схожих изображений (обнаружение → вычисление дескрипторов → сопоставление → фильтрация → ранжирование).
- Развить умение анализировать и сравнивать эффективность различных алгоритмов компьютерного зрения.
- Подготовить студентов к решению прикладных задач (панорамирование, распознавание объектов, 3D-реконструкция).

### 1.2. Воспитательные цели
- Привить культуру экспериментального исследования (систематичность, документирование результатов).
- Стимулировать самостоятельную работу с научной литературой и документацией.
- Развить навыки командной работы (если работа выполняется в парах).

## 2. ПЛАНИРОВАНИЕ ВРЕМЕНИ

Лабораторная работа рассчитана на **4 академических часа** (лекционно-лабораторное занятие) или может быть разделена на два занятия по 2 часа.

| Этап | Длительность | Содержание |
|------|--------------|------------|
| **Вводная часть** | 15 мин | Постановка задачи, обзор инструментов, разбор структуры работы, ответы на вопросы. |
| **Выполнение заданий 1–2** | 40 мин | Реализация детекции ключевых точек, вычисление дескрипторов, визуализация. |
| **Выполнение задания 3** | 30 мин | Сопоставление дескрипторов между двумя изображениями, визуализация совпадений. |
| **Выполнение задания 4** | 30 мин | Фильтрация RANSAC, оценка гомографии. |
| **Выполнение задания 5** | 45 мин | Реализация поиска по коллекции изображений, ранжирование. |

## 3. РЕКОМЕНДАЦИИ ПО ОРГАНИЗАЦИИ РАБОТЫ

### 3.1. Форма выполнения
- **Индивидуально** – для закрепления навыков программирования.
- **В парах** – рекомендуется при недостатке вычислительных ресурсов или для стимулирования обсуждения и взаимопомощи (при этом отчёт должен отражать личный вклад каждого).

### 3.2. Подготовка рабочего окружения
- Убедиться, что на компьютерах установлен Python 3.8+ и OpenCV с модулем `contrib` (для SIFT, SURF). Например:
  ```bash
  pip install opencv-python opencv-contrib-python
  ```
- Для работы с SIFT в новых версиях OpenCV может потребоваться патентная лицензия, поэтому рекомендуется использовать версию 4.5.x или переключиться на бесплатные альтернативы (например, `opencv-python-headless` и `opencv-contrib-python-headless`).
- Предоставить студентам набор тестовых изображений (или указать источники для скачивания).

### 3.3. Вариативность заданий (предотвращение копирования)
Чтобы обеспечить уникальность работ, можно предложить каждому студенту (или паре) **индивидуальный набор изображений**:

- Выдать каждому студенту свою пару изображений (эталон и сцена с объектом).
- Для задания 5 (поиск по коллекции) можно использовать общий набор изображений, но запросное изображение выдавать индивидуально.
- Также можно варьировать обязательные к сравнению детекторы/дескрипторы: например, один студент сравнивает SIFT и ORB, другой – SURF и BRISK, третий – A-KAZE и FREAK, и т.д.

Пример вариантов:
| Вариант | Детектор | Дескриптор | Фильтрация |
|---------|----------|------------|------------|
| 1 | SIFT (DoG) | SIFT | RANSAC |
| 2 | FAST | ORB | RANSAC |
| 3 | Harris | FREAK | RANSAC |
| 4 | SURF (Hessian) | SURF | RANSAC |
| 5 | A-KAZE | A-KAZE | RANSAC |

Можно также предложить студентам самостоятельно выбрать метод для сравнения.

### 3.4. Вспомогательные материалы
- Предоставить шаблон отчёта (структура, требования к оформлению).
- Дать ссылки на документацию OpenCV и примеры кода.
- Подготовить краткую памятку по основным функциям:
  - `cv2.xfeatures2d.SIFT_create()`, `cv2.xfeatures2d.SURF_create()`
  - `cv2.ORB_create()`, `cv2.BRISK_create()`, `cv2.AKAZE_create()`
  - `cv2.BFMatcher()`, `cv2.FlannBasedMatcher()`
  - `cv2.findHomography()` с флагом `RANSAC`
  - `cv2.drawMatches()`, `cv2.drawKeypoints()`

## 4. ОЖИДАЕМЫЕ РЕЗУЛЬТАТЫ И КРИТЕРИИ ОЦЕНКИ

### 4.1. Эталонные результаты
Для типового набора изображений (например, здание и его фрагмент) ожидается:

- **Количество обнаруженных ключевых точек**: SIFT ~2000-5000, ORB ~1000-2000, BRISK ~500-1500 (зависит от порогов).
- **Количество корректных совпадений после RANSAC**: не менее 30–50% от исходного числа совпадений.
- **Время выполнения**: SIFT и SURF медленнее (несколько секунд), ORB и бинарные методы – быстрее (доли секунды).

При выполнении задания 5 (поиск по коллекции) система должна корректно ранжировать изображения: изображения, содержащие тот же объект, должны занимать первые места. Ошибки возможны при сильных изменениях освещения, ракурса или при наличии похожих паттернов.

### 4.2. Критерии оценки (детализация)

| № | Критерий | Макс. балл | Пояснение |
|---|----------|------------|-----------|
| 1 | **Задание 1. Детекция ключевых точек** | 15 | Корректная работа детекторов, визуализация, сравнение количества. |
| 2 | **Задание 2. Дескрипторы** | 15 | Вычисление дескрипторов разными методами, анализ размерности и времени. |
| 3 | **Задание 3. Сопоставление** | 15 | Правильное сопоставление, визуализация матчей. |
| 4 | **Задание 4. RANSAC** | 20 | Корректная фильтрация, вычисление гомографии, визуализация inliers. |
| 5 | **Задание 5. Поиск в коллекции** | 15 | Ранжирование изображений, обоснованный выбор лучшего метода. |
| 6 | **Качество кода и комментариев** | 10 | Читаемость, модульность, наличие пояснений. |
| 7 | **Оформление отчёта** | 10 | Структура, полнота, графики/таблицы, выводы. |

При выставлении оценки можно использовать шкалу: ≥85 – «отлично», 70–84 – «хорошо», 55–69 – «удовлетворительно», <55 – «неудовлетворительно».

## 5. ТИПИЧНЫЕ ОШИБКИ СТУДЕНТОВ И СПОСОБЫ ИХ ПРЕДОТВРАЩЕНИЯ

| Ошибка | Причина | Рекомендация преподавателю |
|--------|---------|----------------------------|
| Неправильная установка OpenCV (отсутствие модуля xfeatures2d) | Студенты устанавливают только базовый пакет. | Заранее проверить наличие `opencv-contrib-python` в требованиях. |
| Сопоставление дескрипторов разной размерности | Использование несовместимых детектора и дескриптора. | Напомнить, что каждый детектор обычно используется со своим дескриптором (SIFT→SIFT, ORB→ORB). |
| Неверное использование RANSAC (например, без проверки достаточного числа точек) | Недостаточное количество совпадений. | Объяснить необходимость проверки количества точек перед вызовом `findHomography`. |
| Путаница между `cv2.BFMatcher` и `cv2.FlannBasedMatcher` | Непонимание различий. | Показать примеры использования обоих методов. |
| Слабые выводы по сравнению методов | Отсутствие системного подхода. | Предложить шаблон для сравнения (таблица с точностью, временем, количеством точек). |
| Некорректная работа с изображениями (разные размеры, цветовые пространства) | Не учтены требования функций OpenCV. | Напомнить о необходимости перевода в灰度 (cv2.cvtColor). |

Рекомендуется периодически обходить студентов, проверять промежуточные результаты и давать оперативные советы.

## 9. РЕСУРСНАЯ БАЗА

- **Набор изображений**: рекомендуется использовать известные датасеты, например, COIL-100, Oxford Buildings, или собственные фотографии объектов с различными ракурсами.
- **Альтернативные библиотеки**: если OpenCV вызывает трудности с установкой, можно использовать `scikit-image` или `kornia` (для PyTorch), но основной упор делается на OpenCV.
